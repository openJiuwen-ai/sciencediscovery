# Execution 状态观察规则 v2

本规则更新于 2026-09-24，适用于 Runner 已确认接受的受管 Shell Execution。
此前版本（提交 `63b5167a`）使用连续两分钟不可达作为 `unknown` 阈值；本版改为连续失败次数，以明确区分单次网络波动和持续不可达。

- API 只查询原 Execution ID，不因状态查询失败重新提交命令。
- 仅连接失败、查询超时、远端 Runner 暂时未连接等可重试的观察错误计数。成功获取一次 Runner 状态后，连续失败计数清零；即使该状态仍为 `running`，也视为一次成功观察。
- 连续第 1～4 次观察失败时，本地 Execution 保持待确认状态并继续查询；连续第 5 次失败时，记录 `unknown`、`unconfirmed` 和最后的连接错误。`unknown` 不代表远端命令失败或停止。
- 提交回执丢失、Runner 身份不匹配、结果未提交版本等情况不套用此重试规则，仍按各自的不确定性处理。

验收：模拟 4 次失败后成功、成功观察后失败计数清零，以及连续 5 次失败；三种情况都不得重复提交命令。
