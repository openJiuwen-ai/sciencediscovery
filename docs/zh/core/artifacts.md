# 科研产物：让研究结果可以继续使用和复核

Agent 的回答可以解释结果，但真正需要交接、复现或继续研究时，一段聊天通常不够。ScienceDiscovery 将有价值的文件登记为 Artifact，使报告、代码、表格、图像和其他研究输出成为可以查看、下载、版本化和继续处理的对象。

Artifact 的重点不是“把文件放进某个目录”，而是明确：**这是本次研究正式交付的结果。**

## Workspace 保存过程，Artifact 表示交付

工作区（Workspace）承载研究过程中的文件，例如：

- 上传的数据；
- 临时代码；
- 中间结果；
- 下载的材料；
- 最终报告。

其中并不是每个文件都需要成为 Artifact。只有当一个结果值得用户继续查看、下载、复核或作为下一步输入时，才应该登记为产物。

可以简单理解为：

> Workspace 是工作台，Artifact 是交付物。

因此，“文件已经写入工作区”和“结果已经交付为 Artifact”是两个不同状态。

## 一个 Artifact 可以不只是最终报告

不同研究任务可以交付不同类型的产物：

- Markdown / PDF 研究报告；
- Python、R 或 Shell 脚本；
- CSV / JSON 结果表；
- 图像和可视化；
- 模型输入、候选方案或其他可复用文件。

高质量交付通常不只保留结论，还保留足够的过程材料。例如数据分析任务可以同时交付脚本、关键结果表和报告，使后续复核不必从聊天记录重新推断方法。

## 版本让“改了什么”可以被检查

同一科研产物可能经过多轮修改。版本记录帮助回答：

- 哪次修改产生了当前结果；
- 两个版本之间有什么差异；
- Reviewer 的意见修正了什么；
- RSI 搜索最终选择的版本和起点有什么不同。

版本并不自动证明新版本更正确。它提供的是可比较的历史；改进是否成立，仍取决于评价、证据和实验。

[科研产物 RSI](evolve.md) 正是围绕“一个可以评价的产物”进行多轮候选搜索和比较。

## Artifact 是其他可信机制的落点

ScienceDiscovery 的多项能力都围绕产物展开：

- **Reviewer**：针对具体产物版本指出引用、计算或证据问题；
- **ScienceMemory**：记录任务、文件、引用和结论之间的关系；
- **RSI**：比较和改进可评价的产物版本；
- **Domain workflow**：最终把真实科研案例交付成文件，而不只停在聊天回答。

因此，Artifact 是从“Agent 做过一些事情”走向“研究结果可以被检查”的重要边界。

## Artifact 不等于正确答案

把文件登记为产物，只说明它被正式交付，不代表：

- 其中所有事实都已核实；
- 代码没有错误；
- 引用一定支持对应论断；
- 统计方法适合当前问题；
- 结果已经经过同行评议。

重要结论仍应检查其来源、计算过程和适用边界。Reviewer 与 ScienceMemory 可以帮助定位问题，但也不替代科研验证。
