# 专业 Specialist：把研究经验变成可复用的分工

同一个研究项目里，检索资料、分析数据和审视结论需要不同的关注点。每次都从头解释工作标准，既费力，也容易遗漏。Specialist 让你把一种专业角色的职责、指令、技能与连接器整理成可复用的配置。

它可以是一位专注来源质量的文献研究者，也可以是一位先检查缺失值与样本范围的数据分析助手。名称帮助识别角色，真正决定工作方式的是明确的任务说明，以及它能够使用的资源。

## 让“擅长什么”变得具体

一个有用的 Specialist 应说明三件事：接收什么输入，负责哪些判断，交付什么结果。例如，文献检索角色可以交付去重后的来源与覆盖缺口；它不必同时承担实验设计和最终报告撰写。

技能承载可复用的工作方法，连接器提供可调用的数据或工具接口。将它们与角色指令配在一起，可以减少重复准备，也让任务分工更清晰。模型与运行环境仍需按实际运行配置，不应把一个角色名称理解为另一套独立算力。

## 专业角色仍需要协作

主 Agent 分派任务时可以指定 Specialist，由它在职责范围内执行，再将结果用于整体研究。角色分工并不保证一定会并行，也不意味着每位专家的输出天然正确；主 Agent 仍需要检查交付、整合重复内容并处理意见分歧。

良好的交接应包含文件或产物、简短结论和未解决的问题。这样，后续角色可以沿已有结果继续工作，而不必重新检索全部资料或复制大段中间文本。

## 从最常重复的工作开始

在 **系统配置 → Specialists** 中查看内置角色或创建自己的角色，填写名称、职责说明与指令，配置所需技能和连接器。首次使用可以采用默认配置，等某类任务反复出现后，再提炼成专门角色。

![专业角色配置](../../images/specialist.png)

专业化的收益来自稳定的方法与清楚的分工。赋予“专家”称号不会带来专业资格，也不会替代实验验证。把交付要求写具体，往往比加入更多角色更有帮助。
