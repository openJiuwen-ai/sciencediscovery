# 技能库管理 M2 落地

M2 目标是把技能库从“可用”推进到“好用”：召回质量更高，冲突更容易发现，版本质量能被看见，旧技能管理入口逐步迁移到库模型。

## 要解决的问题

M1 后，运行时已经能挂载库并做基础召回。但字符串检索对大规模技能库不够稳定，冲突也主要停留在结构层面，用户和自演进页面还缺少清晰的版本质量视图。

M2 重点提升：

- 召回质量。
- 语义冲突诊断。
- 版本评估可视化。
- 旧 `/api/skills` 与 SkillManager 的迁移体验。

## 交付内容

- 将 `/api/skill-libraries/search` 从简单字符串检索升级为混合召回。
- 为技能库版本保存评估指标历史。
- 增加语义冲突诊断结果类型。
- SkillManager 支持库、版本、diff、rollback 和评估摘要。
- 旧 `/api/skills` 保留兼容，但内部逐步走库模型。

## 混合召回

建议召回信号包括：

- `name` 精确匹配。
- `description` 文本匹配。
- `domainTags` 过滤与加权。
- `triggers` 匹配。
- 向量相似度。
- 技能历史命中率或评估分。

接口保持不变，只替换内部排序和索引实现，避免影响应用层循环。

## 冲突诊断

M2 可以新增 `SkillConflictDiagnostic`：

```ts
interface SkillConflictDiagnostic {
  level: "warning" | "error";
  skillIds: string[];
  reason: string;
  evidence: string[];
}
```

第一版可只做 warning，由用户或应用层决定是否阻塞。只有结构冲突继续由框架强制阻塞。

## 版本质量视图

每个库版本可以展示：

- 版本号、content hash、创建时间。
- 相对上一版的 diff。
- 自演进评估指标。
- 相对 baseline 的提升或回退。
- 回滚入口。
- 本版本是否被历史 Prompt Manifest 引用过。

## 验收标准

- 搜索结果质量明显优于纯字符串匹配。
- 同一个 query 能结合标签、触发条件和向量结果排序。
- UI 能查看库版本历史、diff、评估摘要和回滚。
- 语义冲突能以 warning 形式展示。
- 旧技能管理入口仍可用，不破坏已有工作流。

## 暂不做

- 不让框架直接决定自演进是否成功。
- 不自动删除历史技能包。
- 不保证语义冲突诊断零误报；它是辅助信号，不是最终裁决。
