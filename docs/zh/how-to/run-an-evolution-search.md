# 运行一次演进搜索

在会话里驱动 `/evolve-design`：提出搜索、定规模、看过程、读结果。搜索是什么、什么时候根本不适用，见[程序演进](../explanation/evolve.md)；要一次能完整跑完的第一次运行，见[教程](../tutorial/02-evolve-a-solution.md)。

## 开始之前

- 在 **系统配置 → 全局默认值** 配好任务模型。
- 沙箱执行可用 —— 候选在 bubblewrap 里评测，用 `--skip-sandbox-check` 启动的服务跑不了搜索。
- 一个起点，和一个能给它打分的东西。两者都在提方案的过程中与你一起设计，事先都不需要存在。

## 1. 提出搜索

在输入框里说清楚要改进什么、"更好"是什么意思：

```text
/evolve-design 写一对处理文本的 compress/decompress。必须无损往返，只用标准库，
不许用 zlib/lzma/bz2。分数是压缩比。
```

`/evolve-design` 不是必须的 —— 用自然语言描述目标会走到同一个技能 —— 但打出来会弹出算法选择器。

![写方案前先在 PUCT 与 OpenEvolve 之间选择](../../images/evolve/choose-algorithm.png)

| 算法 | 维护什么 | 什么时候选它 |
|---|---|---|
| **PUCT**（默认） | 一棵候选树 | 在一个起点上持续精炼 |
| **OpenEvolve** | 多岛 MAP-Elites 归档 + 环形迁移 | 解空间宽、容易早熟收敛 |

也可以直接写在命令里：`/evolve-design --algorithm openevolve …`。

## 2. 回答四个检查点

技能会和你一起设计这次搜索，中间停四次。每次停都是几行让你过一眼的东西，不是一张表格。

1. **"更好"是什么** —— 可测量的判据、什么被冻结、起点是什么。
2. **评分方案** —— 写出评测器并对起点跑一次，给你看它得了多少分，外加一句话说明这套评分奖励什么。这一站值得认真读：衡量错东西的判据就是在这里被逮住的。问问自己候选可以做什么来拿更高分，以及那是不是你真正想要的。
3. **运行规模** —— 单元、各分片大小、扩展预算。
4. **启动结果** —— 探针的两个数，以及搜索接下来会做什么。

说"你决定"或"直接跑"，技能会在一条消息里把余下的选择都讲明然后不停顿地跑完。

### 想自己把关的话

| 旋钮 | 建议 |
|---|---|
| 一个单元 | 一次测量消耗的量。要大到同一个候选测两次得分相同 —— 单元里只装一条会让分数变成二值，并且浪费预算，因为搜索会跳过它已经解掉的单元。 |
| `gate` 分片 | 三者中最大。确定性评分 8–12 个单元，带随机性的 16–24。这是搜索唯一据以排名的数。 |
| `rollout` 分片 | 四个以上，绝不为一，且不超过 gate。 |
| `test` 分片 | 4–8 个。它全程不参与，买的是对最终数字的信心。 |
| `expansions` | 至少 `4 × workers`。按要走多远：已知缺陷 4–6，换思路 12–20，从零写 20 以上。 |

总量放不下时，缩小每个单元，不要砍 gate。

### 怎么选起点

起点必须**包含搜索要改进的那个机制**，并且是能跑的形态。候选修改的是摆在它面前的东西；起点里没有这个机制，就逼得每个候选从零发明它，而从零实现的失败率远高于在已有代码上修改。

两次实测能说明问题。一个缓存任务以能用的 LRU 起步，0.2218 → 0.9396，候选在已有策略之上换进了 ARC、LIRS、TinyLFU。一个压缩任务以恒等编码起步 —— 它"能跑"但什么都不压，也就没有任何东西可供修改 —— 十次扩展全花在从零写整个压缩器上，其中七个根本跑不起来，最终停在 0.226。

起点另外需要的是**提升空间**：分数瞄准 **0.3–0.7**。0 没有可依托的东西，满分则无处可爬。

## 3. 看着它跑

![运行中的分数图、搜索树与候选流水](../../images/evolve/live-panel.png)

- **分数图** —— 每个候选一个点，阶梯线是当前最优，虚线是起点基线，结束后标出留出 `test` 分。没跑起来的候选是标出来而不是藏起来。
- **搜索树 / 图** —— 谁派生自谁。
- **候选流水** —— 每个版本的父节点、改动摘要和得分。

OpenEvolve 运行多一个**网格**视图展示归档 —— 每岛一列，★ 是全局最优，↔ 是迁移来的，每格标出复杂度/多样性坐标。

运行在后台继续。关掉面板不会停止它，会话可以同时做别的事。

## 4. 读结果

![起点与最优版本是同一产物的两个版本](../../images/evolve/result-versions.png)

起点和最优版本是同一产物的两个版本，所以结果是一份 diff，并且可以从任一版本再次发起搜索。

![起点与最优候选的对比](../../images/evolve/result-diff.png)

**看留出 `test` 分，不要看最好的 `gate` 分。** gate 那个数引导过搜索，按构造就是偏乐观的；test 分片全程没参与。两者差距大意味着搜索拟合了它能看见的分片。

开启[科学记忆](../explanation/science-memory.md)后运行也在图谱里：搜索节点通过 `input` 边关联起点、`produces` 边关联结果，节点详情带基线分与留出测试分。

## 不顺利的时候

| 你看到的 | 意味着 | 怎么办 |
|---|---|---|
| 方案在搜索开始前被拒 | 判别力探针发现：评分分不开正常程序与被弄坏的程序、起点没有提升空间、重复评测不稳定，或失败诊断不带定位信息 | 按拒绝理由改。这是最便宜的失败 —— 不花预算 |
| 平线运行：所有候选分数相近 | 评分没有判别力，或单元太小 | 放大单元，检查用例是否真的奖励你在意的东西 |
| 大量候选"没跑起来" | 起点里没有可供修改的机制，候选只能从零重写全部 | 换成一个包含该机制、能跑起来的版本重新起步 |
| 没有任何候选超过起点 | 这是结果：在这套评分下这些变体赢不了起点 | 重新考虑评分，而不是你希望候选采取的路子 |
| 最好的 gate 分远高于 test 分 | 搜索拟合了它可见的分片 | 扩大 gate 分片后重跑 |
