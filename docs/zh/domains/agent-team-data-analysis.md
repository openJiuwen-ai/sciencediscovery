# 用 Agent Team 进行免疫特征数据分析任务

本例参考“脓毒症免疫分型共识分析”（BiomniBench-DA，DA-14-1），展示如何让 Agent Team 完成数据分析、结果复核和报告。

案例资料描述了约 3,948 名患者的 38 项免疫特征评分。目标是找出哪些评分在患者之间一起变化，并将变化相近的特征归为一组。这里聚类的对象是**特征**，不是患者。

案例题目和原始数据可通过下方的 Hugging Face 链接获取。下载所需文件后，即可参照本指南发起分析；文中的两张案例图用于说明怎样阅读结果。功能介绍见 [Agent Team](../core/agent-team.md)。

## 1. 准备数据和环境

先完成[快速开始](../getting-started/quick-start.md)，确认当前会话可使用 `science-research-team`，分析、复核和报告所需的内置专家已启用，代码执行环境可用。

从 Hugging Face 获取案例题目和所需文件：

- [查看案例题目与任务要求](https://huggingface.co/datasets/phylobio/BiomniBench-DA/blob/main/da-14-1/instruction.md)。
- [下载案例所需数据文件](https://huggingface.co/datasets/phylobio/BiomniBench-DA/tree/main/da-14-1/environment/data)：打开目录，按题目要求下载所需文件。

将评分表上传到会话，并说明：

- 每行代表什么，例如一位患者或一次采样。
- 哪些列是免疫特征评分，哪些是患者编号、队列或其他信息。
- 缺失值如何表示，同一患者是否可能出现多行。

示例中将数据文件称为 `scores.csv`，使用时替换为真实文件名，并提供评分列清单或数据字典。不要把患者编号、队列编码等列当作评分一起分析。

## 2. 提出分析请求

```text
请使用 science-research-team 分析我上传的 scores.csv。
每行代表一名患者，评分列由随附的数据字典说明。

目标：计算免疫特征评分之间的两两相关性，对特征做层次聚类，
识别一起变化的特征组合。只分析上传的数据，不做文献检索。

先核对样本数、评分列、缺失值和常数列，说明处理方式。
说明选择哪种相关系数、如何转换为距离，以及采用的聚类方法。
评估合理的分组数，不要预先强制分成两组。

请由 code-engineer 完成分析，result-evaluator 复核，
再由 report-writer 整理交付。
输出中文报告 report.md、过程说明 trace.md、分析代码、
相关性矩阵 correlation_matrix.csv、聚类归属表 cluster_assignments.csv、
相关性热图 correlation_heatmap.png 和树状图 dendrogram.png。
说明哪些结果通过复核，还有哪些限制。
```

这些文件名是本次请求指定的交付要求，你可以修改。只做数据分析时，团队主要使用三个角色，不必额外启动文献调研。

## 3. 跟随分析与复核

团队先检查数据并运行分析，然后由复核 Agent 检查结果；需要修改时会返回分析阶段。默认最多进行 3 轮分析与复核。

你可以在会话中的任务和工具记录查看执行过程。若需要补充字段含义或处理异常数据，按提示提供信息。报告中应能找到实际使用的样本数、特征数、缺失值处理和方法选择。

复核应特别关注：

- 相关性是否在患者之间计算，聚类对象是否确实为特征。
- 缺失值处理是否改变了有效样本数，常数列是否得到处理。
- 距离定义与聚类方法是否匹配，分组数是否有依据。
- 更换相关系数或对样本重采样后，主要分组是否稳定。

可以用轮廓系数辅助判断分组是否清晰，用调整兰德指数（ARI）比较不同分析下的分组是否一致。报告应说明比较对象和计算方法；若未做这些检查，就明确标为未验证。

## 4. 阅读图表和结果表

### 相关性热图

每个格子表示两个特征的相关性。下图中红色表示正相关，蓝色表示负相关，颜色越深，相关程度越强。沿对角线出现的色块有助于发现一起变化的特征。

![案例提供的免疫特征相关性热图，红色为正相关，蓝色为负相关](../../images/agent-team/correlation_heatmap.png)

### 层次聚类树状图

树状图展示特征如何逐步合并。分支合并得越低，表示在所选距离定义下越相近。本例图片标题记录了平均连接法与 `d = 1 - r`；你自己的报告也应记录这些选择。

![案例提供的免疫特征层次聚类树状图](../../images/agent-team/dendrogram.png)

两图来自案例资料，用于展示产物形式。最终组数和每个特征的归属应以本次运行的聚类归属表和分析方法为准，不能只靠分支颜色或示意切线判断。

### 报告和过程说明

将图表与 `cluster_assignments.csv` 对照，查看每组有哪些特征。报告应区分数据支持的关系与进一步的生物学解释：相关性本身不能证明因果，也不能直接用于诊疗判断。

`trace.md` 应说明使用了哪些输入、运行了什么代码、复核提出了什么问题，以及如何处理。分析代码和环境说明用于复跑；只有图表或一句“审核通过”还不够。

## 5. 确认交付是否完整

检查约定的文件是否齐全、图表能否打开、表中的特征是否与实际分析列一致，以及报告是否说明复核状态。

如果达到迭代上限仍有问题，团队应交付最新结果并标明分析未完成。你可以根据列出的限制补充数据或调整任务，再继续分析。

换成其他数据时，保留“明确问题 → 检查数据 → 分析 → 复核 → 报告”的过程，并替换数据字段、分析方法和输出要求。
