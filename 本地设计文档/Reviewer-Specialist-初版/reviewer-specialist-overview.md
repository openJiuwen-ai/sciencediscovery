# Reviewer Specialist 运行逻辑概览

Reviewer Specialist 是 ScienceAgent 的只读质量审核模块。它在研究报告等 Artifact 生成后，检查引用、数值证据和来源链路，帮助用户发现需要补充或修订的内容。

## 产品故事（STAR）

**Situation｜情境**：科研报告往往同时包含文献、数值和来源清单。传统格式检查只能发现明显缺漏，无法判断引用是否对应正确论文、数值是否有可追溯证据；而把 `sources.json` 等中间文件混入语义审核，又容易制造无效告警。

**Task｜任务**：为 Agent 生成的研究 Artifact 建立一个可控、可解释的审核层：既要覆盖引用和数值 Evidence 的深度核验，又要限定审核范围，避免影响正常对话和其他 Session 的产物。

**Action｜行动**：设计并实现 Quick/Deep 两档只读审核。Quick 校验结构与来源链路；Deep 将文献 URL 或完整参考文献解析为 DOI、PMID、PMCID，优先 MCP 精确查询、再以 Web Search 验证，并比对数值 Claim 与锁定 Evidence。系统按 Artifact 类型路由，持久化进度和结果，支持取消、重试与语义指纹复用。

**Result｜结果**：形成从 Artifact 锁定、分级核验到对话反馈的完整闭环。叙述型报告获得可行动的引用和数值审核结果；`sources.json` 等元数据仅接受结构/链路检查；来源不足时以 `INCONCLUSIVE` 表达不确定性，避免把基础设施限制误判为内容问题。

## 运行流程

```text
当前 Session 生成 Artifact
        ↓
用户选择 Quick 或 Deep 并发起审核
        ↓
锁定 Artifact 版本与内容哈希
        ↓
按类型路由审核
        ↓
生成结构化结果、进度卡片与后续对话摘要
```

审核只处理当前 Session 产生的 Artifact，不扫描项目中其他 Session 的历史产物。

## 两级审核

| 档位 | 作用 |
| --- | --- |
| Quick | 快速检查 Artifact 结构、引用/Evidence 关联、JSON 可解析性及来源图谱链路。 |
| Deep | 在 Quick 基础上，进一步核验文献身份、引用与相邻论述的支持关系，以及数值 Claim 与锁定 Evidence 的一致性。 |

## 引用与证据核验

对于可识别的文献，系统优先从 URL 或完整参考文献解析 DOI、PMID、PMCID 等稳定标识符：

```text
文献 URL / 完整参考文献
        ↓
解析 DOI、PMID 或 PMCID
        ↓
对应 MCP 精确查询
        ↓
MCP 不可用时，Web Search 按同一标识符验证
```

表格中的“作者 + 年份”短引文会先关联到参考文献小结中的完整条目，再进入严格匹配。系统不会仅凭模糊关键词认定文献匹配。

## Artifact 类型边界

| 类型 | 审核方式 |
| --- | --- |
| Markdown 报告、研究简报等叙述型产物 | 可进入引用、数值 Claim 与 Evidence 语义审核。 |
| `sources.json` 等中间元数据/来源清单 | 仅检查 JSON 可解析性和 Artifact 来源链路；不进入 Citation、数值 Claim 或 Evidence 语义审核。 |

## 结果与交互

审核过程和结果以持久化卡片展示，包括运行进度、通过、告警、失败、取消和可复用结果。审核发现会以简洁摘要进入后续对话上下文，用户可据此要求 Agent 修订报告。

`INCONCLUSIVE` 表示来源内容不足、无法精确匹配或查询基础设施不可用，因而无法可靠判断；它既不代表报告通过，也不直接等同于报告存在错误。

## 安全与控制

- 审核为只读操作，不会自动修改用户的报告或来源文件。
- 同一 Session 内的审核串行执行，避免结果交叉覆盖。
- 支持取消、部分进度、独立重试与未变更内容的结果复用。
- 执行过程记录脱敏审计日志，用于问题定位，不作为用户对话内容直接展示。
