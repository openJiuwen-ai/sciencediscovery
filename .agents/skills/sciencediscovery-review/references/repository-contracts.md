## Contracts that change review decisions

- `package.json`, `pnpm-workspace.yaml`, `tsconfig.base.json`, `tsconfig.tests.json`: Node >=22.19, pnpm 11.1.2, TypeScript workspace plus Python services. Test sources are excluded from product builds but checked by the root test tsconfig. Preserve quoted Node test globs and the lockfile. Python service dependencies and test runners belong to their own project environments.
- `scripts/component-boundaries.mjs` and `scripts/check-architecture.mjs`: package public export boundaries, acyclic workspace dependencies and browser-safe exports. New component wiring should not bypass these by broadening allowlists without a real architectural reason.
- `packages/governance/src/permission-policy.ts` and `permission-runtime.ts`; `services/runner/src/environment-access.ts`, `request-auth.ts`, `sandbox-launch.test.ts`, `sandbox-network-contract.test.ts`: examine the permission action/resource scope, current epoch and environment revision, auth, path/mount and network isolation together. `createPermissionEpoch` snapshots network access with `structuredClone`; legacy `never_ask` authorizations are read as `always_allow`. Changes require tests for scope leakage and persisted-record compatibility.
- `packages/orchestration/src/subagent-pool.ts`, `subagents.ts` and colocated tests: lifecycle permits are FIFO, abortable before acquisition, released idempotently only when execution has settled. Check cancellation and parent/child lifetime through `services/api/src/subagent-continuation.ts`, not merely the pool's counter.
- `packages/workspace/src/artifact-read.ts`, `file-page.ts`, `packages/artifact-manager/src/manager.ts`, `services/api/src/artifact-lifecycle.test.ts`: retain source/version provenance, bounds and truthful pagination. Artifact text has an 8 MiB decodable window and separate page bounds; `hasMore` promises reachable line progression, not recovery of a truncated wide line or bytes beyond that window. Binary data exposes metadata rather than base64 payloads.
- `packages/idea-tree/src/persistence.ts`, `authority.ts`, `runtime.ts`, `composition.ts`: the persistence port is a scoped connection to the Python tree service, not a duplicate state store; preserve revision-conflict and storage-unavailable semantics and executor fingerprint scope. Follow refactors in the target branch rather than assuming this main-branch layout still holds.
- `services/gateway/`, `services/adapter/`, `jiuwen_swarm/`, `scripts/jiuwenswarm.sh` and `docs/en/reference/jiuwenswarm-migration-status.md`: verify the pinned JiuwenSwarm agent path for tools, context, history and permissions. A Node adapter smoke alone does not prove the migrated live backend works.

## Test/compatibility routing

- Read `.github/workflows/ci.yml`, `.ci/README.md`, `.agents/skills/ci/SKILL.md`, and `test/support/tagged/profiles.mjs` for CI changes. PR/release select reviewed Linux amd64 UT/ST/E2E with model none/mock, no NPU and no LLM judge. Daily additionally selects eligible real E2E. Selection is source-tag based; missing credentials fail preflight rather than deleting planned cases. Quarantined, live ST, NPU and macOS coverage are not implicitly validated by PR CI.
- Useful narrow guards: `pnpm architecture:check`, `pnpm typecheck`, `pnpm ci:selftest`, `pnpm ci:catalog:check`, `pnpm test:policy`, `pnpm test:list`; actual layer runs still use the canonical `pnpm ci:*` entrypoints. Do not claim a guard invocation exercised product behavior.
- For Python edits inspect the changed `services/<service>/pyproject.toml`, lockfile and `tests/`; current root examples include `pnpm paper:test`, `pnpm gateway:test`, `pnpm memory-graph:test`, `pnpm evolve:test`. These are targeted checks, not substitutes for shared-plan accounting.
- Read `.agents/skills/e2e-testing/SKILL.md` for browser or public API/CLI/local-stack journeys. Use isolated run data/ports and a local stub unless separately authorized otherwise. The browser setup is committed under `test/` and synchronized into gitignored `.e2e/`; stale manifests are BLOCKED. Journey metadata, numbered user steps, final outcome assertions and preserved reports matter. Browser coverage remains necessary for layout/interaction changes.
- Linux uses Bubblewrap; macOS uses Seatbelt. Inspect platform-specific Runner tests for platform changes and disclose untested platforms. Do not change host security settings under the reviewer skill. Release binaries (x86_64/aarch64) and Docker gates require their own evidence.
